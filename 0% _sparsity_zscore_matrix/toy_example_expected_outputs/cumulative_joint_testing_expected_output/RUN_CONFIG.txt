=============================================
Toy run configuration and reference runtime
=============================================

This folder demonstrates the cumulative joint testing stage end to end on the toy
outputs produced elsewhere in this repo (sampling_method_expected_output/,
score_matrix_expected_output/): cumulative_joint_test_pipeline_toy_run_3panelfigure.py
runs the real-data test and ends in the 3-panel summary figure,
cumulative_joint_test_pipeline_toy_run_table.py runs the same real-data test but ends
in a per-SNP output table instead (see section 3), and
cumulative_joint_test_null_pipeline_toy_run.py runs a matching null (no-signal)
calibration so the real peaks can be judged against it. All three were run directly
on 20,000 SNPs x 100 phenotypes without any job submission (no .sh / sbatch wrapper)
— at this scale each script finishes in well under two minutes, so the
separate-resource-request machinery the full-scale versions use
(Full_scale_run/score_matrix/cumulative_joint_testing/fullscale_run/) isn't needed.

Date run : 2026-07-28

NOTE: all three scripts' path variables (base_out, score_path, z_path, parquet_path,
ldsc_path, and — for script 3 only — pvalue_matrix_npy) are checked in as
"/path/to/..." placeholders, the same convention used elsewhere in this repo — the
values below are what was actually used for this reference run, not what's currently
in the files. Fill in the config block yourself before running any of them.

A note on null_stat_matrix.dat (763 MB)
=====================================================================
This is by far the largest file in this folder and is an intermediate on the way to
the final parquet/figure, not something that needs to exist for reproducibility —
rerunning the script regenerates it deterministically from the fixed seeds above. It
is kept here anyway, matching the precedent set by stat_matrix.dat in
sampling_method_expected_output/ (a reference artifact to diff your own run against
without re-running). It stays under the 1 GB per-file cap, but pushes this folder's
total to ~781 MB, well above every other toy example folder in this repo.


Scaling notes for a full-scale run
=====================================================================
Both scripts' runtime is dominated by the sampling-loop-shaped stages: script 1's
stage 1 and script 2's stage B, whose cost scales with N_snps x Ns in the same way
Fullscale_sampling_loop.py's does. null_stat_matrix.dat (like stat_matrix.dat)
scales with Ns x N_snps x 4 bytes, independent of Np, and is why the full-scale
version of this folder is far larger than 1 GB and is not checked into the repo.
The resolution floor of the empirical p-value is 1/(n_null+1) — at full scale
(~9.6M null SNPs) that floor is ~1e-7, five orders of magnitude finer than this toy
run's 5e-5 floor (20,000 null SNPs).

Script 3's output table scales the same way build_final_output_table.py's does: row
count is N_snps and column count is 1 + Np + 3 regardless of scale, so the file size
scales with N_snps x Np. At full scale (9,611,261 SNPs x 1,010 phenotypes) that table
is ~35 GB, vs. 7.7 MB here (20,000 x 100) — big enough that the full-scale script
reads score_matrix.dat in much larger chunks (CHUNK=500,000 vs. this toy run's 5,000)
and is submitted via sbatch rather than run directly.
