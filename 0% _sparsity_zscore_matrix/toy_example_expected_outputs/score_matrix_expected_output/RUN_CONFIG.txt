=============================================
Toy run configuration and reference runtime
=============================================

This folder demonstrates the score_matrix stage end to end on the toy
outputs produced by sampling_script_toy_run.py (../sampling_method_expected_output/):
generate_score_matrix/ computes score_matrix.dat, then score_vs_|z|/ picks
a single SNP and plots its per-phenotype score against |z| as a sanity
check on the relationship between the two. Use it to sanity-check your own
setup before pointing the scripts at full-scale inputs.

---------------------------------------------------------------------------

2) score_vs_|z|/  (plot_discordant_SNP.py)
=====================================================
Picks one random SNP (np.random.seed(17), N_snps=20_000) and scatters that
single SNP's score against |z| across the 100 toy phenotypes, with an OLS
fit line — a per-SNP check, not per-phenotype, despite the similar-looking
scatter+OLS code as other plotting scripts in this repo.
NOTE: score_path, z_path, parquet_path and out_path in the checked-in
script are still "/path/to/..." placeholders — point them at
../generate_score_matrix/score_matrix.dat,
../../sampling_method_expected_output/Z_matrix.npy, and
../../sampling_method_expected_output/df_toy_allSNPs_allphenos.parquet
before running.

Runtime: effectively instant at this toy scale (one memmap row lookup from
each of score_matrix.dat and Z_matrix.npy, a 100-point OLS fit, one plot).

Scaling notes for a full-scale run
=====================================================
score_matrix.dat size = N_snps x Np x 4 bytes, independent of Ns — it scales
the same way as Z_matrix.npy, so budget disk space accordingly at full scale
(N_snps ~ 9.6M). Peak RAM instead scales with
N_WORKERS * Ns * SNP_BATCH * 4 bytes, driven by Ns and SNP_BATCH rather than
N_snps or Np, so lower SNP_BATCH first if a full-scale run runs out of memory.
plot_discordant_SNP.py stays cheap at any scale — it only ever reads a
single row out of each memmap, regardless of N_snps.
The partial-verification sample size (2,000 rows here) is small relative to
N_snps at any scale and stays cheap even at full scale (~9.6M SNPs) — see
Full_scale_run/score_matrix/Compute_score_matrix.py, which uses a larger
sample (50,000 rows) simply because the far larger row count there makes
that still a small, cheap fraction. The deletion prompt is where this
matters most at full scale: stat_matrix.dat is ~370 GB there (vs. 0.8 GB
here), so confirming score_matrix.dat is good before freeing that space is
the main point of the check, not an afterthought.
